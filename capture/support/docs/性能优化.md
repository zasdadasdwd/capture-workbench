# 性能优化验证（2026-10-01）

使用临时 SQLite 构造 5 万条请求（同一域名、20 个路径、不同查询参数）及一个 8 MiB 未压缩响应。没有修改真实抓包数据。每项测量 12 次，中位数统计；内存使用 tracemalloc，统计 Python 分配峰值。结果只代表本机该数据分布，不代表网络转发吞吐。

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 目录查询中位数 | 684.788 ms | 0.220 ms |
| 8 MiB 响应预览中位数 | 1.400 ms | 0.333 ms |
| 预览 Python 分配峰值 | 8388.9 KiB | 262.8 KiB |
| 完整查看 JSON 大小（原始模式 / 文本模式） | 30,758,402 字节 | 8,388,743 字节 |

目录首次加载仍需遍历数据库，本次约 720 ms；改善的是高频的后续刷新。新增请求和 URL 修改增量维护计数，响应生命周期更新不会重复计数。删除请求会使目录缓存失效后重建；最多保留 8 个会话的目录缓存，随 SQLite 连接淘汰。

未压缩预览只从文件读 64 KiB 加一个字节，保留截断判断。压缩正文仍按原有有界解压处理，这次没有声称降低其完整压缩输入的读取内存。完整查看仅省去展示用不到的原始/解码 Base64；默认 API、编辑、重放和导出继续读取原始字节。

MCP 实时日志使用服务共享快照，文件未变时不重新解析；多个订阅者共享解析结果，隐藏页面停止订阅。日志滚动与追加会自动使缓存失效。

回归覆盖目录计数、URL 修改、删除、并发写入、压缩正文、截断、原始字节保持、日志追加与共享缓存；共 64 项测试通过。

复现：

```sh
PYTHONPATH=. .venv/bin/python capture/support/scripts/benchmark_workbench.py --output capture/support/docs/benchmarks/performance-after.json
.venv/bin/python -m pytest -q
```
