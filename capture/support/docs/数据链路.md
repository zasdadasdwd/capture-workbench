# 三维请求参数关系网

工作台顶部、简便请求详情和完整详情均提供「数据链路 ✦」。独立页面：`http://127.0.0.1:8765/links.html`。

## 使用

1. 选择会话与起点请求。历史会话需显式勾选，详情入口自动带入原会话与请求。
2. 输入参数名或值片段，直接搜索指定范围内全部报文。请求只用作参考点；无论它本身是否包含片段，搜索仍继续。
3. 先看置顶的「响应中的来源线索」，再看每个请求首次出现的时间线。也可浏览起点字段，并在高级选项选择字段转换追踪；该模式默认前后 300 秒、扫描 500 条、显示 100 条。
4. 三维图的参考请求、匹配响应和关联请求分别用蓝、青、黄表示，节点有简短接口标签。完整值一致时才建候选连线，线索面板优先展示响应字段及后续使用数量。点击节点或连线查看可核对的字段与指纹，默认隐藏原值。
5. 拖动旋转、滚轮缩放、点击聚焦；窄窗口里首个响应线索也直接显示在图上。2D 模式支持缩放和平移，无 WebGL 自动降级。高频同接口达到 12 个节点时聚合，可展开。
6. 点击「选取参数继续展开」切换到该请求，选择它的新参数，再分析下一层。不同分支保留已有节点坐标。
7. 保存视图保留任务、布局、相机及人工确认/排除/备注。打开时检查请求是否已删除；图中证据与人工判断分别保存。可导出带证据 JSON 或图像。
8. 当前仍运行的会话可开启实时追踪，每 5 秒增量复核；隐藏页面停止轮询，历史已结束会话不轮询。原始起点保持不变；全文搜索覆盖整个指定范围，字段转换追踪在时间窗结束后停止实时模式。

## 匹配边界

响应字段从响应完成后开始寻找；请求字段从该请求开始时间寻找。允许显示时序重叠时，这类连线明确标为疑似。字段转换追踪默认同时查更早响应中的来源候选、更早请求中的使用和后续发送请求中的使用。全文出现搜索还包含所有后续响应；响应中出现不等于请求使用。

原值、URL 解码、可打印 Base64 解码和 Bearer 前缀可进行轻量转换匹配。包含匹配与短/常见值默认关闭。声明式自定义规则支持 sha256、sha1、md5、hex、strip_prefix（附 prefix）；不执行用户 Python/JavaScript。规则吻合只能作为验证证据，不能证明客户端算法。

字段转换追踪一条请求最多 20 条匹配证据，每次最多扫描 2000 条、显示 500 条；图形最多同时展示 2001 个节点；全文搜索全部匹配仍保留在可分页的出现时间线和任务结果中。页内字段按 100 条分页。字段发现与字段转换追踪正文只解析 64 KiB，过长、截断、解码错误或超出字段上限的部分会提示；未匹配不代表不存在关系。相同值可以有多个候选来源，起点由开发者选择，不自动把时序相邻当成因果。

## 隔离与性能

`AnalysisManager` 单并发编排独立 spawn 子进程；忙时返回 409，不无界排队。`CaptureReader` 使用独立 `mode=ro` SQLite 连接、短查询，释放游标后解析正文；不使用抓包 Store 锁，不更新抓包数据库。

进度通过有界 IPC 队列返回，取消终止子进程，任务超时 90 秒。子进程尝试降低调度优先级并限制地址空间，系统不支持资源限制时仍有扫描/正文/时间上限。独立进程仍共享 CPU 和磁盘，并非绝对零开销。

实时增量按元数据签名复用未变请求的证据，变更与删除重新复核，源请求变化会使全部旧匹配失效。字段索引、结果和视图都存放 `data/analysis/`；索引可能包含敏感原值，文件本机权限 0600。主动勾选原值时生成的字段结果也仅保存本机。分析页面不自动发起重放。

图使用本地固定 Three.js 0.186.1（MIT）资源，实例化节点与批量连线；三维力导向布局在 Web Worker 中计算，按需绘制，没有持续全图动画。第三方许可与版本来源在 `capture/web/vendor/three/`。

## API 与 MCP

- `POST /api/links/jobs`：创建字段发现、全文出现搜索或字段转换追踪任务。
- `GET /api/links/jobs/{id}`：状态/进度。
- `GET /api/links/jobs/{id}/result?offset=0&limit=100`：字段或节点分页；边随关联请求所在节点页返回，支持反向连线。
- `POST /api/links/jobs/{id}/cancel`：取消分析。
- `/api/links/views`：保存/列出视图，`/{id}` 读取/更新。

新增 MCP 工具：`start_data_analysis`、`get_data_analysis_status`、`get_data_analysis_result`、`cancel_data_analysis`、`list_data_analysis_views`。先启动、再轮询、小页读取（默认 20，最多 100），调用继续写 MCP 查询日志。图结果默认只含摘要、字段路径、指纹和证据，没有完整报文。


## 从请求详情开始

在抓包列表或完整请求详情中，直接选中 Cookie、请求头或正文中的参数片段，点击「分析」。系统直接全文搜索所选片段，支持非 JSON 正文和任意选区；不选择文本时，进入参数选择页。

分析范围优先使用勾选的请求，其次当前筛选结果，没有勾选或筛选时使用当前整个会话。全文出现搜索包含起点之前和之后的请求，起点不含片段也继续查找。起点网址查找只用于选择参考请求，不改变分析范围。

当前会话正在记录时，可选择「停止抓包并分析」或「保持抓包，实时追踪」。停止记录不会停止代理转发。实时追踪每 5 秒在独立子进程增量复核：勾选范围固定；筛选范围保留规则，因此包含之后新出现的匹配请求。页面隐藏时暂停轮询。

## 全文出现搜索（默认）

输入参数名（如 `token`）或值片段（如版本前缀），点击「搜索关联」。搜索 URL、请求头名称和值、请求正文、响应头名称和值、响应正文，并包含原始请求。正文流式解压 gzip/deflate/br/zstd，支持非 JSON、超过 64 KiB 的正文和跨读取块的片段。头名称大小写不敏感，URL、头值与正文按字面片段匹配。

全文搜索分批遍历整个范围，不受扫描批大小、字段追踪时间窗及节点上限截断。取消与 90 秒超时仍生效，超时任务不伪装成完整结果；正文缺失或无法解码会明确提示搜索不完整。大量匹配在结果接口与出现时间线分页；图形为避免卡顿同时展示最多 2001 个节点。

出现时间线按请求内首次匹配的报文时间排序（请求开始、响应完成），每个请求只列一次，合并显示其中所有匹配位置和重复次数；点击节点查看各位置时间及证据中的首个字符偏移。原始请求与实际请求分别标注；它们属于同一网络请求，并非两次网络发送。同时间的报文位置按稳定顺序排列，不能推断更精细的执行先后。第一次出现只指当前范围内首次捕获，可能已有未抓到的缓存来源。较早的响应标为来源候选，值片段或字段名一致不能确认参数生成算法。

MCP 使用 `operation="search"`、`query`、`session_id` 和 `flow_id`，并可附 `request_ids` 或 `target_filters`。仍按小页读取结果，避免全部报文送给 Agent。搜索明文仅保存在本机权限 0600 的任务配置中，API 结果和保存视图使用 `query_from` 任务引用恢复查询；审计日志隐藏 `query`。

## 来源优先与图中连线

以商品标签接口为参考请求搜索 `T3_5.8.0_3-1ZqddJBalUZE`，来源线索会先列出 `/api/am3` 的 `response.body#/info/token`：完整值与参考请求一致，后续 25 个请求也携带同一完整值。普通的相同前缀请求仍在时间线，不会遮住来源。

来源排序先看与参考请求完整值是否一致，再看有多少后续请求携带完整值，同分时优先 JSON 响应体。三维图的实线为响应完整值与随后请求字段一致，虚线为完整值在多个请求中先后出现。两者都只是报文层面的候选证据；首次捕获不等于真实生成点。字段太长、非结构化正文或只有片段命中时，匹配仍会在时间线中显示，并在来源线索注明证据强弱。
